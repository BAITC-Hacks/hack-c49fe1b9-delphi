## Ключевые выводы проверки

1. **Успешных прежних тестов было недостаточно.** Агент обращался к отсутствовавшим
   промптам `structure` и `source_search`. Теперь все используемые стадии имеют
   инструкции, схемы, обработку результата и проверки на уровне SDK.
2. **Название не определяет владельца функции.** Одинаковые роли в разных
   подразделениях получают разные ID. Структура учитывает всю известную цепочку
   родителей; одно упоминание не доказывает создание или ликвидацию подразделения.
3. **Отсутствие совпадения не доказывает потерю.** Перед `unmatched` проверяются
   доступные исходные body-блоки After, перед `added` — Before, включая блоки без
   извлечённых функций. Неполный поиск, parse gaps и возможные кандидаты сохраняют
   необходимость review. Many-to-many, split/merged, scope и modality не сводятся
   к сравнению номеров пунктов.
4. **Resume должен учитывать изменившийся каталог.** Принятое extraction
   сохраняется. Если оно не завершено, производные findings/structure/coverage
   пересчитываются после дополнения каталога. При завершённом extraction принятые
   партии поиска используются повторно. Проверенные человеком runs заморожены.
5. **Перевод и решения человека отделены от анализа.** Переводятся сохранённые
   объяснения findings и структуры; цитаты и заметки человека сохраняются.
   Неполный перевод или несовпадение ID не попадают в кеш.
6. **Фоновые задачи уже существовали.** Сохранены `asyncio`/`to_thread`, один
   активный run, checkpoints и recovery; исправлена гонка старта с ожидающим
   resume. Новая очередь, Redis/Celery и автоматическое платное возобновление
   для этой поставки не добавлялись.

## Выполненная проверка

Из `lab/`:

```powershell
.\.venv\Scripts\python.exe -B -m unittest discover -s tests -q
```

**106 тестов, OK**, последний полный прогон — 10.344 секунды. Проверяются
агентные стадии, парсеры, валидация, CLI/API, checkpoints/resume, сохранение,
review, отчёты, перевод и существующий учёт. SDK подставной; агентные проверки
блокируют внешнюю сеть и используют временные данные. Отдельный набор
`agent_costs/tests` не запускался.

Из корня, с отдельным временным `LAB_DATA_DIR` под `lab/.cache/`:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File lab/run.ps1 demo --mode preprocess --allow-limited
```

Результат: **498 + 498 = 996 блоков, `prepared`, 0 API calls, 0 findings**.
Сохранены `result.json`, `sources.json`, `functions.csv`, `report.ru.html`.
Обе редакции имеют `parse_status=limited`: отсутствует приложение 1, в Before
пуст пункт 5.5.3, граница оглавления отмечена предупреждением. Ноль findings
в preprocess означает отсутствие AI-анализа, а не отсутствие проблем.

`git diff --check` прошёл. Проверены синтаксис Python, UTF-8 Markdown, ссылки
документации lab и пути реальных fixtures. Проверка хешей 46 защищённых файлов
подтвердила неизменность оригиналов, `.env`, исторических результатов и журналов
расходов во время offline-проверки.

## Ограничения и следующая работа

**Платный end-to-end и live-перевод не запускались. Качество реальных AI-выводов
этими проверками не подтверждено.** Казахские тексты требуют вычитки человеком.
Покрытие обработки не равно семантической точности; риски используют кандидатов,
а не полный перебор всех пар. Слишком большой каталог структуры остаётся явно
непроверенным, без скрытой обрезки.

Следующая поставка — адаптация lab к UUID/DTO/enum и PostgreSQL основного
приложения, затем проверка checkpoints, source evidence, resume, переводов,
coverage и совпадения UI/экспорта на одном сохранённом результате. SQLite Store
lab не переносится как fallback. Сохраняются существующий один worker и выбранные
экраны/вкладки продукта. После отдельного разрешения нужна семантическая приёмка
реальной пары и RU/KK/EN, с измерением пропусков и ложных срабатываний.

Этот файл — сводка поставки, а не второй план. Задачи и приёмка принадлежат
[implementation-plan.md](docs/implementation-plan.md), контракт переноса —
[backend-lab-alignment.md](lab/docs/backend-lab-alignment.md). Предложения по
просмотру документов и Before/After остаются в [docs/feedback.md](docs/feedback.md).
