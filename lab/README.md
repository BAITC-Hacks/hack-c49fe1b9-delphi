# Delphi lab — документы и один AI-агент

Изолированный компонент обработки документов: один SDK-агент, промпты, контрольные входы, CLI и локальный API. На 23.09.2026 пройдены **106 offline-тестов** и бесплатный preprocess двух настоящих DOCX редакций 8/9. Платный end-to-end текущей реализации не запускался; качество реальных AI-выводов не подтверждено.

Лаборатория использует **Python 3.12 + FastAPI + Pydantic + SQLite + OpenAI Responses API**, один процесс и один ограниченный агент. SQLite — существующее изолированное хранилище lab, не fallback и не замена PostgreSQL основного продукта. [Общая архитектура](../docs/architecture.md) сохраняет PostgreSQL, async SQLAlchemy и Alembic. `/docs` лаборатории — API-консоль, интеграция с продуктовым React UI остаётся отдельной задачей.

## 1. Быстрый старт в Windows

Из корня репозитория:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File lab/bootstrap.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File lab/run.ps1 demo --allow-limited
```

Первая команда устанавливает зафиксированные зависимости в `lab/.venv`, кеш — в `lab/.cache`. Вторая запускает **preprocess**, без API-ключа и расходов на модель. Она читает оба настоящих DOCX редакций 8 и 9 из `docs/sources/`. Markdown остаётся контрольным экспортом.

`--allow-limited` явно принимает ограничения чтения: в реальном комплекте нет содержимого приложения 1, в редакции 8 пуст пункт 5.5.3. Без этого флага документы сохраняются как черновик, анализ не начинается. Список предупреждений выводится до запуска.

Результат команды содержит путь к HTML-отчёту. Откройте его в браузере. В той же папке находятся:

- `result.json`: состояние, текстовые кандидаты, покрытие, AI-выводы при живом запуске, trace и usage;
- `sources.json`: оригинальный текст, документы, номера пунктов и контекст;
- `functions.csv`: извлечённые AI-функции; после preprocess содержит только заголовки;
- `report.ru.html`: сохранённый отчёт с источниками, доступна печать в PDF.

Результаты анализа находятся в `lab/data/runs/<run_id>/`; SQLite и копии входных файлов — тоже в `lab/data`. Отдельные журналы стоимости записываются в `agent_costs/out/lab/<run_id>/`. Эти данные, ключи и окружение исключены из Git. Исходники лаборатории доступны для коммита по решению команды.

### Что уже было выполнено

Последняя проверка: **2 DOCX, по 498 блоков, всего 996**, состояние `prepared`, ноль API-вызовов и findings. Созданы `result.json`, `sources.json`, `functions.csv`, `report.ru.html` в отдельном временном `LAB_DATA_DIR` под `lab/.cache/`. Обе стороны сохраняют `parse_status=limited`: приложение отсутствует, в Before пуст 5.5.3, граница оглавления требует осторожности. Это проверка чтения и текстового сравнения, **не оценка качества AI**. PDF/XLSX проверены сгенерированными синтетическими файлами. Исторический частичный live run не продолжался; `.env`, оригиналы, старые результаты и журналы стоимости не изменены.

## 2. Первый живой запуск агента

```powershell
if (-not (Test-Path lab/.env)) { Copy-Item lab/.env.example lab/.env }
```

Заполните `lab/.env` локально:

```dotenv
OPENAI_API_KEY=ваш_ключ_OpenAI_Platform
OPENAI_MODEL=gpt-6-sol
```

Не помещайте ключ в чат, документ или промпт. Ключ используется только Python-процессом. `OPENAI_MODEL` должен быть доступен вашему API-проекту и поддерживать Responses, Structured Outputs и function calling. `gpt-6-sol` указан как настраиваемая стартовая модель по [официальному описанию](https://developers.openai.com/api/docs/models/gpt-6-sol); доступ на вашем аккаунте и качество ещё не проверены.

Начните с короткого **явно синтетического** примера:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File lab/run.ps1 demo --fixture ru --mode live
```

Затем можно обработать настоящую пару:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File lab/run.ps1 demo --mode live --allow-limited
```

По умолчанию: 40 API-вызовов, 900 секунд, до 5000 выходных токенов на запрос, до 4 раундов инструментов, один повтор временной ошибки. Вызовы последовательные. Реальная пара может исчерпать этот стартовый бюджет ещё на извлечении: 966 блоков вне оглавления обрабатываются партиями до 16 блоков. Увеличивайте лимиты в `.env` после просмотра `usage`, покрытия и расходов API-проекта. `LAB_MAX_CALLS` — ограничение числа запросов, **не денежный лимит**. Необработанные ID остаются в coverage; исчерпание бюджета даёт `partial`, не успешное завершение. Полный результат на реальных документах всё равно сохраняет ограничения отсутствующего приложения.

Режим `live` отправляет текст загруженных документов в OpenAI. В Responses выставлено `store=false`; это настройка API, а не обещание нулевого хранения по всем политикам провайдера. Кредиты **Brev** в этом прототипе не используются: отдельный GPU-сервер и модель не развёрнуты. Подключение другого провайдера требует отдельного адаптера и проверки инструментов/схем, замена одного URL здесь не предусмотрена.

### Автоматический учёт стоимости

**После интеграции используйте обычный `lab/run.ps1`. Отдельный launcher `python -m agent_costs.lab_run` больше не нужен:** он отклоняет запуск новой лаборатории, чтобы не подключить учёт дважды. Ручной `PYTHONPATH`, дополнительная установка `agent_costs` или вторая команда для отчёта не требуются.

Учёт включён по умолчанию для `demo/analyze --mode live`, API-запусков и перевода сохранённых результатов. Отключение: `LAB_COST_TRACKING=0` в `lab/.env` или окружении. `preprocess` не вызывает модель и не создаёт события стоимости. Попадание в кеш перевода также не создаёт новых событий.

На **каждую фактическую попытку** `Responses.create` сохраняется событие, включая ошибку, повтор и каждый следующий раунд инструментов:

- настоящий `run_id`, `action` (этап), запрошенная и возвращённая модель;
- `attempt` с 1, `round_index` с 0 и `call_index` с 1 внутри экземпляра агента;
- длительность вызова в `elapsed_ms`, ID и статус ответа, `service_tier`;
- полный `raw_usage` SDK и нормализованный `usage` существующего калькулятора;
- оценка USD, разбивка, снимок применённого тарифа либо явная неизвестная стоимость.

В `agent_costs/out/lab/<run_id>/` после каждого события обновляются:

| Файл | Содержимое |
|---|---|
| `events.jsonl` | Журнал всех попыток без ключей, промптов и содержимого документов |
| `report.json` | Суммы и группы по этапам/моделям, неизвестные расходы, ошибки учёта |
| `report.csv` | Те же агрегаты по группам для таблиц |

Перевод дописывает расходы в каталог **того же сохранённого запуска**, включая последующие языки/ревизии проверки. Ответ API анализа содержит снимок `usage.cost_tracking`; ответ нового перевода — такой же снимок в своём `usage`. Актуальный накопленный итог, в том числе после переводов, находится в `report.json`. В конце CLI, включая остановленный анализ, выводятся путь к отчёту и известная сумма USD.

Расчёт использует **существующий** `agent_costs.Tracker/summarize` и `response_prices` из `agent_costs/lab_run.py`. Источник тарифов для прямого OpenAI — `agent_costs/examples/prices.openai-gpt6-sol.json`: точная модель ответа, `service_tier`, порог длинного контекста и отдельные ставки чтения/записи кеша. Тарифы OpenRouter не подставляются, сетевого обновления цен нет. Это оценка по сохранённому тарифу, не счёт провайдера.

`cost_usd=null` означает **UNKNOWN**, а не бесплатный вызов. Так учитываются отсутствующий usage, неподдерживаемая модель/тариф или неопределённая стоимость ошибки SDK. При другом `OPENAI_BASE_URL` прямой тариф не применяется. `known_subtotal_usd` включает только известные оценки; при неизвестных расходах `cost_complete=false`. Ошибка записи метрик выдаёт предупреждение и помечает учёт неполным (`observer_errors`); она не запускает дополнительный запрос, не меняет retry и не отбрасывает результат анализа. Если носитель недоступен полностью, отчёт может остаться устаревшим/недоступным — CLI явно сообщает неполноту.

### Продолжение остановленного запуска и денежный предел

Для того же комплекта можно продолжить `partial`/`failed`/`interrupted` live-запуск:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File lab/run.ps1 resume RUN_ID --max-calls 600 --timeout-seconds 7200 --cost-budget-usd 10
```

Это пример **явного увеличения** прежних ограничений; запускайте его только с согласованным бюджетом. `--max-calls` включает предыдущие попытки данного run, `--timeout-seconds` задаёт время текущего продолжения, `--cost-budget-usd` включает прежние расходы. Рабочий `.env` команда не изменяет. Обычный запуск без новых параметров сохраняет старые ограничения 40 вызовов / 900 секунд.

Продолжение использует сохранённые документы/ID и принятые функции. Уже обработанные блоки не отправляются повторно; оставшиеся разбираются партиями до восьми блоков. История ошибок остаётся в trace. Если извлечение было неполным, производные структура/findings/покрытие сравнения пересчитываются после дополнения каталога. Если извлечение завершено, принятые этапы и партии поиска сохраняются. Модель, документы и fingerprint промптов должны совпадать; legacy-снимок без fingerprint явно отмечается в trace. Проверенный человеком run заморожен для resume. Ревизия перевода повышается, старый кеш не используется. Каталог отчётов и `run_id` остаются прежними.

Денежный ограничитель включается переменной `LAB_COST_BUDGET_USD`. Перед запросом существующий калькулятор резервирует консервативную оценку полного входа и максимального выхода. Резервы сохраняются в `agent_costs/out/lab/<run_id>/budget.json`; известный результат учитывает usage, неизвестный сохраняет отдельный hold без подмены `cost_usd=null`. Непокрытый UNKNOWN или ошибка учёта блокируют новые платные попытки. Для старого extraction-события предусмотрен проверяемый `reserve_unknown_extraction`; к историческому run он в этой работе не применялся. Это предел по сохранённым тарифам, не биллинг провайдера. Второй калькулятор и launcher не нужны.

Успешный проход по всему доступному тексту может оставаться `partial`, если исходные документы неполны. Смотрите отдельно `blocks_processed/blocks_total`, покрытие сравнения/рисков и `parse_gaps`; отсутствие приложения не исчезает после дополнительных запросов.

## 3. Команды для своей работы

Можно работать непосредственно из `lab`:

```powershell
Set-Location lab
.\.venv\Scripts\python.exe -m delphi_lab parse ..\docs\sources\Положение_о_внутреннем_аудите_редакция_8_обезличено.docx
.\.venv\Scripts\python.exe -m delphi_lab analyze --before C:\inputs\old.docx C:\inputs\old-units.xlsx --after C:\inputs\new.docx --mode preprocess --allow-limited
.\.venv\Scripts\python.exe -m delphi_lab history
.\.venv\Scripts\python.exe -m delphi_lab show RUN_ID
.\.venv\Scripts\python.exe -m delphi_lab export RUN_ID --language ru
.\.venv\Scripts\python.exe -m delphi_lab review RUN_ID FINDING_ID confirmed --note "Сверено с владельцем функции"
.\.venv\Scripts\python.exe -m delphi_lab translate RUN_ID --language kk
.\.venv\Scripts\python.exe -m delphi_lab export RUN_ID --language kk
```

Замените `RUN_ID`, `FINDING_ID` и входные пути. `run.ps1` меняет рабочую папку на `lab`, поэтому для собственных входов удобнее абсолютные пути. Выходы анализа остаются в `lab`; журналы стоимости — в `agent_costs/out/lab/<run_id>/`.

Каждый `analyze`/`demo` создаёт новое сравнение. Документы выполненного запуска неизменяемы. Повторный запуск не перезаписывает прежние findings. Для остановленного CLI-процесса предусмотрена команда `recover`; используйте её после его завершения. Один OS-lock не даёт CLI и API одновременно менять одну лабораторную БД. Сервер при старте помечает оставшиеся активные записи как `interrupted` только после получения этой блокировки.

Коды выхода: `0` — подготовка завершена или AI-процесс завершён в пределах условий; `1` — ошибка входа/настройки; `2` — сохранён неполный/ошибочный запуск. `prepared` означает только подготовку, не выполнение AI-анализа.

## 4. API для демонстрации и передачи Осману

Из корня репозитория:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File lab/run.ps1 serve --port 8010
```

Открыть **http://127.0.0.1:8010/docs**. Только localhost, один worker. Не запускайте параллельно CLI для той же папки данных; пользуйтесь API или остановите сервер через `Ctrl+C`. Лаборатория без авторизации и не предназначена для публичного размещения.

Порядок работы в API-консоли:

1. `POST /api/analyses` — создать сравнение и получить `id`.
2. Дважды `POST /api/analyses/{id}/documents` — загрузить файлы с `side=before`, затем `side=after`.
3. `POST /api/analyses/{id}/runs` — выбрать `preprocess`/`live`, язык, `allow_limited`; получить `run_id` сразу.
4. `GET /api/runs/{run_id}` — следить за стадией; выводы и покрытие сохраняются по мере выполнения.
5. `GET /api/runs/{run_id}/report?lang=ru` — открыть HTML. Findings, sources и evidence доступны отдельными маршрутами.
6. `PATCH .../findings/{finding_id}/review` — сохранить решение. `POST .../translations` — перевести сохранённые пояснения, затем запросить отчёт на этом языке.

Дополнительно: `POST /api/runs/{run_id}/resume`, `GET .../functions`, `GET .../structure`, `GET .../costs`. Resume принимает `max_calls` и `timeout_seconds`; денежный предел задаётся конфигурацией процесса. CLI `demo/analyze/resume` также принимают `--max-calls`, `--timeout-seconds`, `--cost-budget-usd`; `estimate RUN_ID --resume` бесплатно оценивает нижнюю границу оставшихся extraction-вызовов, без обещания времени/стоимости.

Старт возвращает 202 и регистрирует `asyncio`-задачу, исполнение идёт через `to_thread`. Второй запуск/resume и review/перевод выполняющегося run блокируются, в том числе до захвата работы потоком. Ошибка фонового preflight сохраняется без тела SDK-запроса. Завершение сервера ждёт зарегистрированные задачи; после аварийного перезапуска OS-lock и recovery сохраняют checkpoints и помечают активные записи `interrupted`. Redis/Celery и распределённой очереди нет.

Lab API не совместим напрямую с основным OpenAPI: отличаются ID, enum и некоторые маршруты. Нет редактирования/удаления документа черновика, отдельного endpoint `repeat` и продуктовых страниц React: создайте новое сравнение. Перенос описан в [lab/docs/backend-lab-alignment.md](docs/backend-lab-alignment.md); интеграция не выполнялась.

## 5. Как устроена обработка

```text
Файлы До/После
  → проверка формата/размера → оригиналы + SourceBlock + SHA256
  → детерминированные текстовые кандидаты
  → live: извлечение функций/иерархии → сопоставление структуры
  → live: many-to-many функций → raw-source поиск по После для несопоставленных
  → live: пересечения/конфликты → обратный raw-source поиск по До для новых
  → проверка ID/сторон/смещений → SQLite + частичные checkpoints
  → отдельная проверка человеком → перевод сохранённых пояснений → HTML/CSV
```

| Модуль | Назначение |
|---|---|
| `delphi_lab/parsers.py` | DOCX/MD/PDF/XLSX, реальные цитаты, контекст и ограничения чтения |
| `delphi_lab/diffing.py` | Точное/приблизительное текстовое сравнение; не заключение о потере функций |
| `delphi_lab/models.py` | Pydantic-контракты для передачи команде |
| `delphi_lab/agent.py` | Один агент Responses; извлечение, структура, сопоставление, raw-source поиск, риски, перевод |
| `delphi_lab/planning.py`, `provenance.py` | Бесплатная нижняя оценка вызовов и fingerprint файлов промптов |
| `delphi_lab/costs.py` | Адаптер существующего `agent_costs`, без собственного расчёта тарифов |
| `delphi_lab/validation.py` | Дополнительная проверка ссылок на стороне приложения |
| `delphi_lab/storage.py` | SQLite, immutable inputs, атомарные review/revision |
| `delphi_lab/pipeline.py` | Запуск, checkpoints, обработка частичного результата |
| `delphi_lab/reports.py` | Отчёт по сохранённым данным, оригинальные цитаты и CSV |
| `prompts/` | Реально используемая библиотека промптов |
| `fixtures/` | Короткие RU/KK/EN входы и отдельная карта ожиданий для человека |

Инструменты агента: `search_clauses`, `get_clause`, `get_unit_functions`, `check_references`. Агент не получает shell, файловую запись или внешние поисковые инструменты. Текст документов обрабатывается как недоверенные данные, а не команды. Промпты не содержат заранее подготовленных ответов из `expected.json`.

Цитаты берутся из `SourceBlock.original_text`; LLM возвращает ID и при необходимости смещения. Неизвестная ссылка — ошибка. Перенос требует доказательств каждой указанной функции с обеих сторон; пересечение/конфликт — двух функций и двух источников «После». Для `unmatched` проверяются все исходные body-блоки After, для `added` — Before, включая блоки без извлечённых функций. Неполный поиск или найденный кандидат даёт `review`, а не отсутствие. Сохраняются reviewed/candidate IDs, ошибки и полнота. Ограниченный лексический поиск не является доказательством отсутствия.

Human review не меняет AI-вывод. Его версия увеличивается атомарно; переводы кешируются по `run_id + review_revision + locale`. Отчёт строится из согласованного снимка findings и решений, отклонённые замечания вынесены отдельно. Модель переводит только сохранённые title/explanation/recommendation findings и explanation структуры, отдельными партиями; источники и заметки человека не отправляются на перевод. Неполный ответ/изменённые ID не кешируются. Цитаты сохраняются, повторный анализ при смене языка не выполняется.

## 6. Границы первого демо

- Это лабораторный компонент, **не весь продукт** из командного плана. Чат, согласование несколькими сотрудниками и новая «оптимальная» редакция положения сюда не входят.
- Реальная пара проверяет чтение двух DOCX. Структура хранит иерархию и retained/newly_listed/transformed/unmatched с источниками; дата создания или ликвидации подразделения не выводится из одного упоминания. Одинаковые имена под разными родителями различаются.
- Many-to-many сопоставления, reverse search и `added` реализованы. `unclassified_after_function_ids` перечисляет ещё не завершённые проверки. Возможный counterpart исходного пункта без надёжной связи функций сохраняется как вопрос человеку.
- Риски проверяются для всех обработанных функций «После», с поиском ранжированных кандидатов. Это не исчерпывающая проверка каждой возможной пары. Процент семантической точности не измерен.
- DOCX: абзацы и таблицы, настоящие номера пунктов, родительский контекст. Автоматическая нумерация не выдумывается. Word-страницы не определяются. Изображения, вложения, tracked changes и текст вне основного тела дают ограничения.
- PDF: текстовый слой, страницы; без OCR. Порядок чтения колонок/таблиц требует проверки. Пустой скан не считается обработанным документом.
- XLSX: строки и адреса ячеек, базовая таблица «Подразделение / Функция / Подчинённость» и эквиваленты EN/KK. Формулы не вычисляются, оргсхемы в рисунках не читаются. Старые `.doc`/`.xls` не поддержаны.
- Лимиты: 20 MiB на файл, до 80 MiB распакованного Office ZIP, до 10 000 блоков/2 млн символов, PDF до 200 страниц, XLSX до 20 листов/10 000 строк/64 колонок. Текстовое сравнение ограничено 20 секундами и 2000 блоками «До»; необработанные ID перечисляются явно.
- Промпты одни, на английском, язык вывода — параметр RU/KK/EN. Формулировки KK и входное смысловое сопоставление на KK/EN ещё требуют живого запуска и вычитки. Некоторые технические поля/диагностика лаборатории остаются на английском; полноценная локализация продуктового UI — отдельная работа команды.
- Нет готового развёртывания NVIDIA/Brev, OCR, embeddings/vector DB, прав разных организаций, Docker/deploy. Сохраняемые локально входы и отчёты доступны владельцу рабочей папки.

Контрольные сценарии и ожидаемые **ручные** сопоставления: [fixtures/README.md](fixtures/README.md). Промпты и объяснение выбора языка: [prompts/README.md](prompts/README.md).

## 7. Проверки без платных запросов

Из корня репозитория:

```powershell
Push-Location lab
.\.venv\Scripts\python.exe -B -m unittest discover -s tests -v
Pop-Location
```

Тесты подменяют SDK и блокируют внешнюю сеть. `test_agent_semantics.py` выполняет настоящие стадии: схемы, промпты, иерархию, many-to-many, raw-source sweeps, пагинацию, неполные ответы, неверные ID/доказательства, checkpoints/resume и перевод findings/структуры. Workflow проверяет БД/API/отчёты и продолжение через подставной SDK, включая фоновые ошибки и защиту от второго запуска. Parser checks читают оригинальные DOCX только для проверки; PDF/XLSX создаются как синтетические временные файлы. Учёт и retries также проверяются на временных журналах без реальных ключей.

Результат: **106/106** тестов лаборатории прошли (23.09.2026). Отдельный набор `agent_costs/tests` в этой работе не запускался; калькулятор не менялся. Проверки не доказывают семантическое качество реальной модели.

Бесплатная проверка оригиналов в отдельной временной папке, из корня:

```powershell
$labPreviousDataDir = $env:LAB_DATA_DIR
try {
    $env:LAB_DATA_DIR = '.cache/acceptance-' + [guid]::NewGuid().ToString('N')
    powershell -NoProfile -ExecutionPolicy Bypass -File lab/run.ps1 demo --mode preprocess --allow-limited
} finally {
    $env:LAB_DATA_DIR = $labPreviousDataDir
}
```

Данные этой проверки остаются в `lab/.cache/acceptance-*` для просмотра и не затрагивают `lab/data/`. Последний результат — 996 блоков, `prepared`, ноль AI-вызовов. Платный end-to-end и переводы реальной пары не запускались. Текущая точка передачи — [handoff](docs/handoff.md).
