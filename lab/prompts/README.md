# Промпты лаборатории

`system.md` применяется ко всем этапам одного агента. `extract.md` извлекает
структуру и атомарные функции; `compare.md` сопоставляет их и проверяет кандидатов;
`risks.md` проверяет комплект «После»; `translation.md` переводит только сохранённые
пояснения. Код в `delphi_lab/agent.py` читает эти файлы при запуске.

Промпты написаны на английском; язык пояснений задаётся `language=ru|kk|en`.
Три отдельные копии системного промпта не нужны. Официальные названия и доказательства
сохраняют язык оригинала. Внутренние краткие поля action/object/scope/condition
нормализуются моделью на английский для межъязыкового поиска. Качество такого поиска
и казахского делового языка нужно измерить на контрольных документах; переключатель
языка сам по себе этого не доказывает.

Structured Outputs ограничивает форму ответа. Код отдельно проверяет существование
ID, сторону источника, смещения, покрытие и фактические поисковые операции. После
исчерпания бюджета результат частичный. Промпты не содержат готовых ответов для
реальной пары документов и не обещают юридической оценки.

API: [Responses и инструменты](https://developers.openai.com/api/docs/guides/function-calling),
[Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs).
Доступ модели и качество на ваших документах требуют отдельного живого запуска.

## Ограничения первого запуска

Первичное извлечение берёт до 16 блоков за запрос и дополнительно ограничивает
объём текста. Длинные исходники не обрезаются: слишком большой одиночный блок
остаётся непроверенным с ошибкой. Лимит ответа по умолчанию — 5000 токенов; ответ,
прерванный провайдером, не считается обработанным батчем.

Полная реальная пара может не уложиться в 40 вызовов и 900 секунд. Эти значения
защищают начальный эксперимент; время, бюджет и качество ещё не измерены живым
запуском. Информационные предупреждения, например отсутствие надёжных номеров
страниц DOCX, сохраняются в журнале. Полноту чтения определяет parse_status;
статус limited блокирует безусловный вывод о пробеле.

Проверка пересечений/конфликтов охватывает все обработанные функции «После», но
использует ранжированных кандидатов и ограниченный поиск, а не все возможные пары.
Функции «После» без сопоставления отражаются в
`coverage.unclassified_after_function_ids`. Они пока не объявляются новыми:
для этого нужен отдельный обратный поиск по всему комплекту «До».
