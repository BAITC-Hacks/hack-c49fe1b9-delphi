# Backend ↔ lab: границы текущего переноса

Обновлено: 23.09.2026. Текущая задача разрешает фазу 1: перенести проверенные
наработки lab в основной backend и подключить существующий frontend. Новые live
и E2E не входят в этот объём; отдельный demo-дизайн — будущая фаза 2. Прежний
снимок сравнения после pull (`09cc7b2` / `71b320c`) исторический и больше не
описывает текущую реализацию.

Основной продукт остаётся на FastAPI, PostgreSQL, async SQLAlchemy, Alembic,
одном worker и одном ограниченном агенте. Lab использует SQLite только для
исследований. Копирование её Store или добавление SQLite fallback в продукт
не является способом интеграции.

## Что переносится

| Область | Контракт и граница проверки |
|---|---|
| Источники | Продуктовые UUID и структурированные locator остаются каноническими. Цитаты восстанавливаются из сохранённого original_text; lab ID и строки locator не импортируются напрямую |
| Извлечение | Явные роли, области действия, parent_unit_id, общие владельцы и many-to-many связи. Неустановленный исполнитель остаётся неопределённостью |
| Отсутствие / новая обязанность | Полный проход по доступным сырым источникам After перед возможной потерей и Before перед новой обязанностью. Лексические кандидаты и каталог извлечённых функций не доказывают отсутствие |
| Структура / риски | Сопоставление структуры отдельно от функций; дублирование и потенциальный конфликт требуют двух After-источников и учёта исполнителя/области |
| Checkpoints / resume | Сохранять принятые результаты по партиям с проверкой ID и транзакциями PostgreSQL. Продолжение использует прежний замороженный набор источников, а не новые lab ID |
| Перевод | Переводятся сохранённые пояснения findings, структуры и продуктового заключения; source IDs, оригинальные цитаты и человеческие отметки сохраняются. Учитывается review_revision |
| Стоимость | Используется существующий agent_costs. Реальные попытки, раунды и переводы должны учитываться отдельно; ошибка учёта не должна вызывать повторный платный запрос. UNKNOWN не равен нулю |
| Frontend | Контракт — продуктовый OpenAPI / HeyAPI и существующий защищённый proxy, а не лабораторные dict-ответы. Переключение языка не повторяет анализ |

Общий итог интеграционных проверок принадлежит
[backend README](../../backend/README.md), [плану](../../docs/implementation-plan.md)
и [frontend README](../../frontend/README.md). В этом документе не объявляется
проверенным live-качество или новый браузерный E2E.

## Проверенный перенос парсеров

[Продуктовые парсеры](../../backend/app/parsers) теперь сохраняют контекст
ненумерованных ролей и не переносят внутренний заголовок списка на следующую
соседнюю обязанность. TOC исключается только по явному стилю, лидеру/странице или
повтору уже встреченного заголовка; неоднозначный текст сохраняется с предупреждением.
В XLSX строки остаются целыми, числовые значения не становятся номерами пунктов,
а заголовок таблицы становится родительским источником каждой строки своего листа.

Добавлены границы: 2048 ZIP-элементов, проверка путей/сжатия/DTD и XML entities,
200 PDF-страниц, 20 листов XLSX, 10000 строк и 64 столбца, 10000 исходных блоков,
2 млн извлечённых символов. Размер распаковки по-прежнему ограничен конфигурацией
продукта. Длинный текст делится до 8000 символов с точными смещениями; превышение
общего лимита отклоняет файл, а не выдаёт молча усечённый результат.

PDF сохраняет предупреждение о порядке чтения и не выполняет OCR. Необычная
табличная схема, формулы, непрочитанные вложенные DOCX-таблицы и визуальный контент
остаются явными ограничениями. Поддержка рекурсивного чтения вложенных таблиц lab
не переносилась под видом устранённого предупреждения.

Локально выполнены **38 тестов** из
[test_parsers.py](../../backend/tests/test_parsers.py) и Ruff. Тесты проверяют
оба настоящих DOCX, 318 пунктов DOCX9↔Markdown9, исходные смещения, контекст ролей,
TOC, таблицы и отклонение небезопасных/слишком больших входов. Это проверка чтения
документов, а не AI-выводов. Исходные DOCX и сохранённые исторические результаты
не менялись.

## Несовместимости, которые должны оставаться явными

| Область | Lab | Основной продукт |
|---|---|---|
| Хранилище | Локальный SQLite Store | PostgreSQL, транзакции, advisory lock |
| ID | Строки document/run/function/source | UUID, замороженный реестр источников |
| Locator | Строка с местом и смещениями | Структурированные paragraph/cell/page/offset |
| TOC | Сохраняется как kind=toc, затем исключается из функций | Исключается при парсинге, без отдельного TOC-источника |
| Parse status | ok / limited / error | pending / parsed / partial / failed |
| Подразделение | kind=unit | kind=department; остальные значения проверяются по схеме |
| Finding | preserved / rephrased / added / unmatched / review | retained / reworded / new / potentially_missing / changed; структура отдельно |
| Issue | none / conflict / uncertainty / gap | null / potential_conflict / insufficient_evidence; пробел связан с типом изменения |
| Покрытие / стадия | Лабораторные поля и source_sweeps | Типизированные product coverage/stage, смысл множеств проверяется отдельно |
| API | Локальное исследовательское API | Стабильные operation_id и единая схема ошибок |

Самого clause_no недостаточно для привязки источника: номер повторяется,
перенумеровывается и может сменить смысл. Результат старого lab run нельзя
импортировать в PostgreSQL без явной сверки документов, хешей, locator, фрагмента
и всех ссылок. Новая версия парсера не изменяет прежние сохранённые источники.

## Граница полученных результатов

В lab последний автономный прогон — 93 теста: 92 успешных, один существующий
необязательный пропуск. Preprocess реальных DOCX дал 996 блоков, 30 TOC и 966
блоков основного текста. Новый синтетический live был остановлен до полного
end-to-end; известная сумма расходов не является полной из-за unpriced-вызова.
Точные run IDs и граница нового live сохранены в [handoff](handoff.md).

Эти результаты не доказывают правильность переноса в продукт сами по себе.
Окончательные продуктовые проверки выполняются отдельно, без нового платного
анализа и E2E в текущей фазе. Оценка семантики RU/KK/EN, живой полной пары и
визуальный demo-дизайн остаются самостоятельными последующими задачами.

Итог текущей фазы 1: 127 автономных backend-тестов, Ruff и frontend lint/typecheck/build проходят; миграция 0003 применена локально, drift отсутствует. Продуктовое продолжение сохраняет принятые стадии; прерванная исходная поисковая партия/проход проверяется заново, а не возобновляется с отдельного блока. Нового live/E2E нет.
