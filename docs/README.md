# Документация Delphi

Delphi сравнивает комплекты организационных документов «До / После», отслеживает передачу обязанностей и показывает выводы с источниками.

**Текущий статус:** frontend подключён через HeyAPI и защищённый Next.js proxy. Проверены миграции, seed, базовые HTTP-сценарии, lint, typecheck и build. В фазе 2 прошли Playwright-проверки реального входа и документов, синтетических результатов, проверки человеком, экспорта и мобильного UI; генерируется отчёт со скриншотами. Реальный AI ещё требует проверки; дизайн demo-frontend — фаза 3.

## Правила обновления

- Обязательные требования определяются ТЗ и инструкцией организаторов; выбранная реализация описана четырьмя документами выше.
- UI-решения меняем в product.md, API/данные — в architecture.md, задачи/приёмку — в implementation-plan.md, факты образцов — в source-analysis.md.
- Новые возможности сначала отмечаем как план, а реализованными называем после проверки кода и основного сценария.
- Важные решения из прежних планов объединены здесь. Параллельные спецификации и генерируемые копии Word больше не поддерживаются.
- Изменённые контрольные примеры храним отдельно от оригиналов; выводы по ним обозначаем как синтетические.
- Команды backend и статус их проверки поддерживаются в backend/README.md; наличие команды не означает, что она уже выполнена.

**Выбранная архитектура:** один модульный FastAPI-сервис, PostgreSQL, async SQLAlchemy + Alembic и один агент с инструментами. Next.js + TypeScript frontend использует Better Auth, TanStack Query и сгенерированный HeyAPI-клиент. Детали — в [architecture.md](architecture.md) и [frontend-конвенциях](guides/frontend-coding-conventions.md).
