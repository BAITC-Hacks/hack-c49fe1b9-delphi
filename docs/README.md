# Документация Delphi

Delphi сравнивает комплекты организационных документов «До / После», отслеживает передачу обязанностей и показывает выводы с источниками.

**Фаза 1 завершена:** агентная логика lab перенесена в основной FastAPI backend и существующий Next.js frontend. Реализованы поиск по исходным Before/After, проверка источников, PostgreSQL checkpoints/продолжение и перевод структуры. OpenAPI/HeyAPI обновлены; миграция `0003` применена локально. Автономные проверки и frontend lint/typecheck/build прошли; полного live/E2E в этой фазе не было.

**Текущая фаза 2:** по отдельному поручению дизайн `demo-frontend` перенесён в подключённый frontend. Каталог demo обновлён из `origin/main` до `231811e`; дизайн-код совпадает с `45b3372`, последующие изменения затронули снимки и конфигурацию Vercel. Из remote обновлялся только каталог demo. В продукте теперь тёмно-синие токены, локальные Inter/JetBrains Mono, верхняя навигация, история, реальные зоны загрузки, сводные карточки, очередь/таблица проверки, сгруппированные Before/After-цитаты, точная подсветка по проверенным Unicode-смещениям и ограниченное сравнение слов. API, авторизация, RU/KK/EN и сохранение review остаются продуктовыми; зашитые demo-данные не перенесены.

Проверены frontend lint/typecheck/build и 16 автономных тестов evidence/очереди. После финальной доработки экрана анализа прошли 10/10 выбранных Playwright-проверок результатов и мобильной навигации; [браузерный отчёт](../frontend/docs/report/latest.md) обновлён. Результаты и переводы в этих сценариях синтетические, вход в приложение настоящий; проверка мобильной истории охватывает оболочку, а не доступность backend. Это не полный pipeline E2E и не live AI. Команды и границы — в [frontend README](../frontend/README.md).

**Лаборатория:** 93 offline-теста — 92 успешных и один пропуск; preprocess двух реальных DOCX — 996 блоков, 30 оглавления и 966 основного текста, без модели. Ранее начатый короткий live-тест остановлен; точный статус и неполный учёт расходов — в [lab handoff](../lab/docs/handoff.md). Продукт сохраняет PostgreSQL/UUID; JSON-импорт исторических lab-результатов не добавлялся. [Граница переноса](../lab/docs/backend-lab-alignment.md).

## Правила обновления

- Обязательные требования определяются ТЗ и инструкцией организаторов; выбранная реализация описана четырьмя документами выше.
- UI-решения меняем в product.md, API/данные — в architecture.md, задачи/приёмку — в implementation-plan.md, факты образцов — в source-analysis.md.
- Новые возможности сначала отмечаем как план, а реализованными называем после проверки кода и основного сценария.
- Важные решения из прежних планов объединены здесь. Параллельные спецификации и генерируемые копии Word больше не поддерживаются.
- Изменённые контрольные примеры храним отдельно от оригиналов; выводы по ним обозначаем как синтетические.
- Команды backend и статус их проверки поддерживаются в backend/README.md; наличие команды не означает, что она уже выполнена.

**Выбранная архитектура:** один модульный FastAPI-сервис, PostgreSQL, async SQLAlchemy + Alembic и один агент с инструментами. Next.js + TypeScript frontend использует Better Auth, TanStack Query и сгенерированный HeyAPI-клиент. Детали — в [architecture.md](architecture.md) и [frontend-конвенциях](guides/frontend-coding-conventions.md).
