## Расхождение frontend ↔ architecture.md и как закрыть

`architecture.md` §4 описывает гранулярный API: `POST /api/analyses` (черновик) → `POST /api/analyses/:id/documents` (side) → `POST /api/analyses/:id/runs` → `GET /api/runs/:run_id` → `GET /api/runs/:run_id/findings` → `.../evidence` → `.../sources/:source_id` → `PATCH .../review` → `report`, `functions.csv`.

Фронт реализует **композитный контракт** (таблица в `frontend/README.md`): один `POST /api/analyses` multipart → `{analysis_id, run_id}`, опрос `GET /api/runs/:run_id`, один агрегат `GET /api/analyses/:id` → `AnalysisResult`, `GET /api/analyses/:id/sources/:document_id/:clause_id`.

**Рекомендация (2 часа до дедлайна):** Осман реализует внутренние модели по architecture.md, а наружу отдаёт композитные эндпоинты — это меньше ручек и UI работает сразу. Маппинг полей Finding → `FunctionMapping`/`Risk` описан в `frontend/README.md`. Альтернатива — переписать `frontend/src/lib/api.ts` под гранулярный API (~45 мин, поля ответов не специфицированы, будет угадывание). Решить в первые 10 минут нового чата вместе с Османом.
