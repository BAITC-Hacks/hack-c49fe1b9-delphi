# Delphi — реализация и приёмка за 5 часов

Статус текущей реализации: фазы 0/1 — данные и frontend подключены и проверены. В фазе 2 прошли 10 Playwright-тестов и 10 тестов генерации отчёта; исправлено восстановление старого фильтра при быстром поиске. [Последний отчёт](../frontend/docs/report/latest.md) содержит 18 состояний страниц. Вход и загрузка используют реальный backend, результаты — явно отмеченные синтетические fixtures. Проверка реального AI остаётся открытой; фаза 3 — отдельный demo-frontend дизайн. Пятичасовой план ниже остаётся планом приёмки, а не перечнем уже пройденных AI-проверок.

**Цель:** загрузить два комплекта → сравнить структуру и обязанности → проверить источники → сохранить заключение.

**Команда:** Осман — backend, данные и агент; Нурдауалт — UI, интеграция и запуск; Рауан — контрольные примеры, переводы, проверка, README и демонстрация.

[Навигация](README.md) · [Что строим](product.md) · [Как устроено](architecture.md) · [Проверенные изменения](source-analysis.md) · [Feedback по документам](feedback.md)

Зафиксированные решения:

- Дублирование и потенциальные конфликты входят в обязательный объём.
- Принимаем комплекты файлов; сохраняем связи многих старых функций со многими новыми.
- Три страницы и три вкладки; обработка — состояние экрана результатов.
- Один агент; код отвечает за источники, сохранение, валидацию и экспорт.
- База MVP — PostgreSQL, async SQLAlchemy и Alembic. FindingEvidence связывает вывод с проверяемыми источниками. Better Auth обеспечивает вход и регистрацию в отдельной БД frontend; backend User остаётся подготовкой, JWT и применение ролей не реализованы.
- Backend — модульный монолит: тонкий API → сервисы → модели, парсеры и агент. Ответы типизированы, operation_id стабильны для сгенерированного клиента HeyAPI.
- Переводим UI, пояснения и отчёт; цитаты остаются оригинальными.
- История — список сохранённых сравнений. Повторный запуск создаёт новое сравнение.
- Небольшие улучшения из командных материалов: ссылка на вывод, кликабельная сводка, запоминание языка и проверка загружаемых файлов.
- Казахские/русские/английские черновые подписи и питчи находятся в [product.md](product.md); не требуются отдельные Word-копии.

3. Владелец frontend отображает согласованные поля на выбранных трёх вкладках; сверить UI и серверный отчёт для одного run/review_revision/языка, включая partial и ручные решения.
4. Только отдельным разрешённым поручением выполнить платную семантическую приёмку: 3.4, 5.4.4→5.3.3, 9.15, synthetic missing/overlap/conflict/distinct-scope, RU/KK/EN. Измерять пропуски и ложные срабатывания, не выдуманный процент точности.

В текущей lab-задаче платные вызовы запрещены, основной backend/frontend не читались и не менялись. Исторические результаты, расходы и оригиналы сохранены. Команды и точный статус — [lab/README.md](../lab/README.md), передача — [lab handoff](../lab/docs/handoff.md).

### Передача результатов между участниками

- **Осман → Нурдауалт, до 20-й минуты:** схемы и примеры ответов, ID источников, enum состояний, адреса запросов. При изменении контракта сообщить сразу.
- **Рауан → Осман, до 60-й минуты:** входные контрольные примеры и ожидаемые находки. Ожидания не помещаются в пользовательский запрос к модели как готовые ответы.
- **Нурдауалт → Рауан, до 120-й минуты:** доступный основной путь и список ещё не подключённых частей.
- **Рауан → команда, с 120-й минуты:** конкретный дефект, вход, ожидаемое/фактическое поведение и источник; самые важные исправления первыми.
- **Осман + Нурдауалт, до 180-й минуты:** один совместный проход на настоящих данных.

### Если отстаём

- Нет корректного извлечения к 60-й минуте: сначала чинить чтение и источники; не начинать украшения.
- Нет реального переноса к 120-й: уменьшить размер батчей, разобрать промежуточные результаты; не подменять AI-ответ заранее написанной карточкой.
- Не закрыты must-have к 180-й: отказаться от CSV, проверки внутренних ссылок и перевода полных документов; завершить HTML-отчёт и обязательные проверки. Последние две возможности изначально не входят в основной объём.
- Время ограничено: история остаётся простым списком; локализация — словари плюс пояснения/заключение, без перевода всех документов.
- Не готов деплой к 240-й: обеспечить проверенный локальный запуск и инструкцию. По имеющейся инструкции публичный URL не является безусловным требованием.
- Не прошёл обязательный сценарий/формат: исправить либо явно зафиксировать незавершённость. Не считать такой результат полностью соответствующим ТЗ.

| RU / KK / EN | Нет пропавших кнопок/ключей; неопределённость сохранена; источники не меняются |
| Короткие KK/EN примеры | Проверено именно сопоставление входных текстов, отдельно от перевода интерфейса |
| История / обновление страницы / перезапуск сервера | Завершённые результаты и проверки сохранены; прерванная работа помечена |
| Повторный запуск / двойное нажатие | Старый запуск не повреждён; нет дублирующего активного задания |
| Ошибка API / перевода | Ошибка видна; частичные данные не выдаются за завершённый анализ |
| Экспорт | Те же findings, источники, язык и статусы, что в выбранном запуске UI |
| Чистая установка | Другой участник запускает проект по README без устных дополнений |
| PostgreSQL и миграции | Схема создаётся Alembic; нет зависимости от SQLite и скрытого создания таблиц приложением |
| OpenAPI / HeyAPI | JSON-схема описывает ответы и ошибки; operation_id уникальны и стабильны; клиент генерируется без ручного дублирования DTO |
| Один исполнитель | Второй worker отклонён advisory lock; повторный старт не меняет состояние работающего экземпляра |
| Частичная загрузка | allow_partial требуется явно при пробелах; неполный анализ не объявлен завершённым |
| Перевод во время проверки | Изменение review_revision во время запроса модели возвращает 409 и не сохраняет устаревший перевод |

Автоматизируем важные проверки парсинга, ID, сохранения и известных смысловых случаев. Визуальные подписи, переносы текста и короткое демо проверяем вручную. Для качества AI отмечаем найденные ожидаемые случаи, пропуски и ложные срабатывания; не публикуем вымышленный общий процент точности.

## 4. Коротко, простыми словами

**Delphi сравнивает старые и новые документы и показывает, кто теперь за что отвечает.**

- **Три страницы:** история, загрузка документов, результаты.
- **В результатах:** подразделения, обязанности и вопросы, готовое заключение.
- **Главные действия:** загрузить → сравнить → открыть доказательство → проверить → скачать.
- **Три языка:** русский, казахский, английский. Исходные цитаты сохраняются.
- **Главная особенность:** понять, что обязанность передали другому отделу, а не потеряли.
- **Вторая особенность:** каждый вывод открывает точное место в документе.
- **Третья:** заметить, что обязательное действие стало необязательным.
- **Техническая основа:** React, FastAPI, PostgreSQL и один AI-агент; сейчас подготовлен только backend.
- **Порядок работы:** сначала документы и доказательства; затем сравнение; затем проверка и отчёт; затем языки, история и финальная проверка.
